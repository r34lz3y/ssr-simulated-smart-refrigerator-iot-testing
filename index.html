Fridge-01: build a simulated smart refrigerator

A complete guide to a realistic fake appliance with temperature sensing, defrost mode, MQTT, a web interface, and remote control. Built for testing, troubleshooting, and learning to protect real IoT devices.

Purpose and ground rules

This project creates an intentionally insecure lab device that reports temperature, runs a defrost cycle, and accepts remote commands, the way a poorly built store display cooler or smart refrigerator does. It is meant for security testers, IT staff, students, and anyone learning to troubleshoot or defend IoT devices. Use it to learn how IoT devices communicate, practice troubleshooting, and see how attackers find weak ones.

For testing and education only
  • Run it only in a lab you own, on an isolated network.
  • Never expose the intentionally weak settings (open MQTT, no web login, default passwords) to the internet or your home network.
  • Only test devices and networks you own or have written permission to test.
  • This is a target you build for safe practice. It is not a tool for attacking real devices.

Task 2: State machine and simulated sensors

sudo -u fridge vim /opt/fridge/fridge.py
import random, threading


class Fridge:
    def __init__(self):
        self.lock = threading.Lock()
        self.state = "COOLING"
        self.setpoint = 3.0
        self.temp = 6.0
        self.compressor = True
        self.heater = False
        self.door_open = False
        self.door_left = 0
        self.defrost_left = 0
        self.since_defrost = 0
        self.fault = None

    def command(self, name, value=None):
        with self.lock:
            if name == "set_temp":
                try:
                    v = float(value)
                except (TypeError, ValueError):
                    return
                if -5 <= v <= 10:
                    self.setpoint = v
            elif name == "start_defrost" and self.fault is None:
                self.state, self.defrost_left = "DEFROST", 60
            elif name == "open_door":
                self.door_open, self.door_left = True, 15
            elif name == "inject_fault":
                ok = ("SENSOR_FAIL", "COMPRESSOR_FAIL", "HIGH_TEMP")
                self.fault = value if value in ok else "SENSOR_FAIL"
            elif name == "clear_fault":
                self.fault = None
                self.state = "IDLE"
                self.temp = min(self.temp, 9.0)

    def _doors(self):
        if self.door_open:
            self.door_left -= 1
            self.door_open = self.door_left > 0
        elif random.random() < 0.005:
            self.door_open, self.door_left = True, random.randint(5, 20)

    def tick(self):
        """Advance the simulation by one second."""
        with self.lock:
            self._doors()
            self.since_defrost += 1
            if self.fault is None and self.state != "DEFROST":
                if self.temp > 10:
                    self.fault = "HIGH_TEMP"
                elif random.random() < 0.0002:
                    self.fault = "SENSOR_FAIL"
            if self.fault:
                self.state = "FAULT"
                self.compressor = self.heater = False
            elif self.state == "DEFROST":
                self.compressor, self.heater = False, True
                self.defrost_left -= 1
                if self.defrost_left <= 0:
                    self.state, self.heater = "COOLING", False
                    self.since_defrost = 0
            elif self.since_defrost > 1800:
                self.state, self.defrost_left = "DEFROST", 60
            else:
                if self.temp > self.setpoint + 1:
                    self.compressor = True
                elif self.temp < self.setpoint - 1:
                    self.compressor = False
                self.heater = False
                if self.door_open:
                    self.state = "DOOR_OPEN"
                else:
                    self.state = "COOLING" if self.compressor else "IDLE"
            delta = 0.01 + random.uniform(-0.01, 0.01)
            if self.compressor:
                delta -= 0.06
            if self.heater:
                delta += 0.04
            if self.door_open:
                delta += 0.08
            self.temp += delta

    def snapshot(self):
        with self.lock:
            return {
                "device": "fridge-01",
                "state": self.state,
                "temp_c": round(self.temp, 2),
                "setpoint_c": self.setpoint,
                "door_open": self.door_open,
                "compressor": self.compressor,
                "defrost_heater": self.heater,
                "defrost_left_s": self.defrost_left,
                "fault": self.fault,
            }

Tuning: change the numbers in tick() to make the cabinet warm faster, defrost more often (1800 seconds), or fault more often (0.0002).

Task 3: Verify the simulation

sudo -u fridge vim /opt/fridge/test_sim.py
from fridge import Fridge

f = Fridge()
for i in range(300):
    f.tick()
    if i % 30 == 0:
        s = f.snapshot()
        print(i, s["state"], s["temp_c"], s["compressor"])
f.command("start_defrost")
for i in range(70):
    f.tick()
    if i % 10 == 0:
        s = f.snapshot()
        print("defrost", i, s["state"], s["temp_c"], s["defrost_heater"])
cd /opt/fridge && sudo -u fridge venv/bin/python3 test_sim.py

Expected: temperature falls toward 3 °C and cycles between COOLING and IDLE. During defrost the state is DEFROST with the heater on and temperature rising, then it returns to COOLING after 60 ticks. The simulator has a small random chance of a fault (roughly 7% across this test). If you see FAULT, just run the script again.

sudo -u fridge vim /opt/fridge/mqtt_bridge.py
import json, os, threading, time
import paho.mqtt.client as mqtt

ID = "fridge-01"
HOST = os.getenv("MQTT_HOST", "localhost")
PORT = int(os.getenv("MQTT_PORT", "1883"))
USER = os.getenv("MQTT_USER")
PASS = os.getenv("MQTT_PASS")
CA = os.getenv("MQTT_CA")  # path to a certificate file; set it to enable TLS


def start(fridge):
    c = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id=ID)
    if USER:
        c.username_pw_set(USER, PASS)
    if CA:
        c.tls_set(ca_certs=CA)
    c.will_set(ID + "/status", "offline", retain=True)

    def on_connect(client, userdata, flags, rc, props):
        client.subscribe(ID + "/cmd/#")
        client.publish(ID + "/status", "online", retain=True)

    def on_message(client, userdata, msg):
        name = msg.topic.rsplit("/", 1)[-1]
        fridge.command(name, msg.payload.decode(errors="ignore") or None)

    c.on_connect = on_connect
    c.on_message = on_message
    c.connect_async(HOST, PORT)
    c.loop_start()

    def publish():
        while True:
            c.publish(ID + "/telemetry", json.dumps(fridge.snapshot()))
            time.sleep(5)

    threading.Thread(target=publish, daemon=True).start()

Task 5: REST API and web UI

sudo -u fridge vim /opt/fridge/web.py
import os
from flask import Flask, jsonify, request, abort

PAGE = """<h1>fridge-01</h1><pre id=s></pre>
<button onclick="c('start_defrost')">Start defrost</button>
<button onclick="c('open_door')">Open door</button>
<button onclick="c('set_temp',prompt('Setpoint C','3'))">Set temp</button>
<script>
async function r(){s.textContent=JSON.stringify(await(await fetch('/api/status')).json(),null,2)}
let k='';async function c(n,v){let x=await fetch('/api/command/'+n,{method:'POST',headers:{'Content-Type':'application/json','X-API-Key':k},body:JSON.stringify({value:v})});if(x.status==401){k=prompt('API key')||''}r()}
r();setInterval(r,2000)
</script>"""


def create(fridge):
    app = Flask(__name__)
    key = os.getenv("FRIDGE_API_KEY")

    @app.get("/")
    def index():
        return PAGE

    @app.get("/api/status")
    def status():
        return jsonify(fridge.snapshot())

    @app.post("/api/command/<name>")
    def command(name):
        if key and request.headers.get("X-API-Key") != key:
            abort(401)
        body = request.get_json(silent=True) or {}
        fridge.command(name, body.get("value"))
        return jsonify(fridge.snapshot())

    return app

How to better protect IoT devices

This is the fix list for the weaknesses above, and it applies to any smart device you own or manage. Walk through it on fridge-01 to see each one working.

1. Change default credentials

Default logins are published online and are the most common way devices are taken over. Use a unique, long password per device, kept in a password manager. On the lab: sudo passwd -l admin or delete the account.

2. Isolate IoT on its own network

Use a separate VLAN or guest network and block IoT-to-LAN traffic by default, allowing only what the device needs.

3. Secure the MQTT broker (hands-on) 
sudo mosquitto_passwd -c /etc/mosquitto/passwd fridge
sudo mosquitto_passwd /etc/mosquitto/passwd operator
sudo vim /etc/mosquitto/acl
user fridge
topic readwrite fridge-01/#

user operator
topic read fridge-01/telemetry
topic write fridge-01/cmd/#
sudo chown mosquitto:mosquitto /etc/mosquitto/passwd /etc/mosquitto/acl
sudo chmod 640 /etc/mosquitto/passwd /etc/mosquitto/acl

Replace /etc/mosquitto/conf.d/lab.conf with:

listener 1883
allow_anonymous false
password_file /etc/mosquitto/passwd
acl_file /etc/mosquitto/acl

Create /etc/default/fridge with sudo vim using the lines below (replace the placeholders with your own long values). The device user fridge must use the same password you set in the broker. Then lock the file down and restart both services:

sudo chown root:root /etc/default/fridge && sudo chmod 600 /etc/default/fridge
MQTT_USER=fridge
MQTT_PASS=your-long-password
FRIDGE_API_KEY=another-long-secret
sudo systemctl restart mosquitto fridge

Now anonymous publishing fails, the operator cannot read anything beyond telemetry, and web commands need the header X-API-Key. Your earlier test commands now need credentials:

mosquitto_sub -h 192.168.56.10 -u operator -P 'yourpass' -t 'fridge-01/telemetry' -v
curl -X POST -H 'X-API-Key: your-key' -H 'Content-Type: application/json' -d '{"value":"4"}' http://192.168.56.10/api/command/set_temp

The web page asks for the key the first time a command is rejected, then click the button again.

4. Encrypt with TLS (hands-on) 
sudo mkdir -p /etc/mosquitto/certs
sudo openssl req -x509 -newkey rsa:2048 -nodes -days 365 -subj "/CN=fridge-01" \
  -addext "subjectAltName=DNS:fridge-01,DNS:localhost,IP:127.0.0.1,IP:192.168.56.10" \
  -keyout /etc/mosquitto/certs/fridge.key -out /etc/mosquitto/certs/fridge.crt
sudo chown mosquitto /etc/mosquitto/certs/fridge.key
sudo chmod 600 /etc/mosquitto/certs/fridge.key
sudo chmod 644 /etc/mosquitto/certs/fridge.crt

Add to the Mosquitto config, then restart:

listener 8883
certfile /etc/mosquitto/certs/fridge.crt
keyfile /etc/mosquitto/certs/fridge.key

Point the device at TLS by adding these lines to /etc/default/fridge, then restart it:

MQTT_HOST=localhost
MQTT_PORT=8883
MQTT_CA=/etc/mosquitto/certs/fridge.crt

Capture traffic in Wireshark before and after to see the difference between port 1883 and 8883. Remove the plain 1883 listener once clients use TLS, and change the _mqtt._tcp port in the Avahi file to 8883.

Unverified: this TLS setup uses a self-signed certificate and was not run end to end. Testers connecting from another machine need a copy of the certificate and must connect by a name or address listed in it. Mosquitto's handling of permissions and listener settings can differ between versions.

5. Turn off services you do not use

Disable password SSH (use key-based login), remove telnet, UPnP, and WPS, and close any port you do not need. Re-run nmap -sV fridge-01 and confirm the list got shorter.

6. Never forward ports to a device

Do not expose appliance interfaces to the internet. Use a VPN into your network, or the vendor's cloud with multi-factor authentication.

7. Keep firmware and software updated

Check for updates on a schedule, and replace devices that no longer receive security patches. Prefer vendors with a published update policy.

8. Least privilege

The service already runs as a dedicated account with systemd restrictions. Verify with systemd-analyze security fridge and tighten further.

9. Monitor, log, and keep an inventory

List every connected device, what it talks to, and who owns it. Watch for unusual traffic, such as a refrigerator contacting unknown hosts.

10. Limit data and features

Turn off cameras, microphones, and cloud features you do not need, and review what data the device sends and where.

Known issues and unverified areas

This guide was written without running it on a live system. Treat these as the places most likely to need adjustment, and report what you find.

  • All code and commands: not tested end to end on a fresh Ubuntu 24.04 install or a Raspberry Pi.
  • Interface names and addresses: enp0s8 and 192.168.56.x are examples. Check ip -br a.
  • Hypervisor menu names: adapter and network names differ by product and version.
  • TLS and Mosquitto permissions: see the notes in the protection section. Behavior varies by Mosquitto version.
  • SSH drop-in precedence: verify with sshd -T, as shown in Task 7.
  • mDNS from the tester VM: fridge-01.local only resolves if the tester has an mDNS resolver such as Avahi.
  • HIGH_TEMP fault: the cabinet rarely gets hot enough on its own to trigger it. Use inject_fault with the value HIGH_TEMP.
  • Manual test as root (Task 5): it is a shortcut and can leave root-owned files in /opt/fridge. If the service later fails with permission errors, run sudo chown -R fridge:fridge /opt/fridge.
  • Flask development server: fine for a lab. It is not a production web server.
  • Raspberry Pi hardware sensors: outlined only, not tested.
  • CSRF and retained-message exercises: described from how the code and broker should behave. Confirm them in your lab.

Provided for education and authorized testing. Use it only on systems you own or have explicit permission to test, and follow the laws that apply where you live.
